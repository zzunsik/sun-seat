# 햇빛 좌석 요구사항

> 이 문서는 GitHub 이슈 #1~#18의 범위와 완료 기준을 바탕으로 정리했다. 이슈와 다르면 이슈를 기준으로 고치고 이 문서도 함께 갱신한다.

## 1. 목적

버스·지하철·자가용으로 이동할 때 햇빛을 피하거나(기본) 받을 수 있는 좌석을 구간별로 알려 준다. 개인용 앱이며 스토어에 올리지 않고 APK로 설치한다(#17).

## 2. 사용 흐름

1. **입력**(#11): 출발지(현재 위치 또는 장소 검색), 목적지(장소 검색), 수단(대중교통/택시/자가용), 출발 시각(지금 또는 지정), 햇빛 피하기/받기
2. **경로 후보**(#12): 대중교통은 후보 목록에서 탈 경로를 고른다. 후보 상단의 출발·도착 칸에서 기존 이름을 편집하거나 맞바꿀 수 있다(#70). 편집을 열기만 해서는 검색하지 않으며, 취소는 기존 여정과 후보 상태를 유지한다. 선택 확정·맞바꾸기는 변경한 조건으로 한 번 조회한다. 카드 탭은 같은 경로를 반복해서 눌러도 지도 미리보기만 연다. 좌석 결과는 명시적인 ‘좌석 보기’로 연다(#84). 자가용은 경로가 하나면 바로 결과로 간다
3. **결과**(#13): 탑승 구간별 추천 좌석, 좌·우 노출 비율, 좌·우 타임라인
4. **설정**(#15): 지하철 기본 선호, 기본 모드
5. **최근 장소**(#16): 사용자가 직접 고른 장소의 이름·좌표를 기기에 저장해 즉시 적용

### 2.1 수단별 추천 표현 (#55)

- 버스: 진행 방향 좌·우와 앞~중간/중간~뒤, 창가·통로를 함께 안내한다. 차종별 1인석·2인석 번호는 추측하지 않는다. 응답의 `vehicles.type`이 광역이면 앞보기 좌석 문구를 쓴다. 그늘 쪽에 자리가 없으면 해 쪽 통로를 대안으로 보여 준다. 햇빛 받기는 해 쪽 창가가 우선이다.
- 지하철: 기존 선호에 따른 벤치 추천과 맞은편 창 정면 직사 시간대를 역 구간과 함께 보여 준다. 입석은 해 반대쪽 벤치 앞을 안내한다. 호차 앞·뒤는 옆 창 노출과 거의 관계없으므로 추천하지 않는다.
- 택시: 자동차 경로를 재사용하며 선택 전에 예상 택시 요금을 표시한다. 뒷좌석 좌·우(운전석 뒤/조수석 뒤)를 추천한다. 왼쪽이면 오른쪽 문으로 타서 이동하고 내릴 때도 오른쪽 문을 쓰도록 안내한다. 운전자 눈부심은 표시하지 않는다.
- 자가용: 동승자 추천에서 낮은 정면 햇빛이 있으면 조수석을 제외한다(햇빛 피하기). 운전자 눈부심은 유지한다.
- 버스·지하철에서 반대쪽이 연속 5분 이상 유리하면 자리 변경 시점을 표시한다. 정확한 정류장 시각이 없으면 출발 후 분으로 표시한다. 변경을 따랐을 때의 노출 합계와 시뮬레이션은 같은 추천 결과를 사용한다.
- 혼합 지상·지하 지하철은 역 사이로 나눈다. 역별 좌표·소요시간이 없는 응답은 역 사이를 동일 비율로 나눈 추정임을 화면에 밝힌다. 지상으로 판정된 역 사이만 계산하며 지하·미확인 구간은 제외한다.

## 3. 추천 규칙

### 3.1 공통
- 태양 방위각·고도는 기기 안에서 오프라인으로 계산한다(#3)
- 경로를 선분으로 나눠 선분마다 진행 방향과 통과 시각을 구하고 좌·우 노출을 합산한다(#4)
- 해가 진 뒤에는 추천하지 않는다. 도보 구간은 추천에서 뺀다

### 3.2 버스·자가용(#5)
- 노출이 적은 쪽을 추천한다. 햇빛 받기 모드에서는 반대
- 좌·우 차이가 15%p 미만이면 "차이 없음"
- 버스는 "진행 방향 왼쪽/오른쪽", 자가용은 동승자 좌석(조수석, 뒷좌석 좌·우)으로 표현
- 운전자 눈부심 구간: 태양이 진행 방향 ±20° 안이고 고도 15° 이하인 구간

### 3.3 지하철(#6, #14)
- 좌석이 옆을 보므로 두 벤치의 노출을 모두 보여 준다
- 해 쪽 벤치는 등 직사, 반대쪽 벤치는 해가 낮을 때 정면 직사
- 선호: 등 뒤 햇빛 피하기(기본), 정면 햇빛 피하기, 총 노출 최소
- 지하 구간은 추천에서 빼고 "지하 구간"으로 표시한다. 지상 여부는 공공데이터를 앱에 내장해 판정한다

## 4. 외부 서비스와 제약

### 4.1 장소 검색
- 카카오 로컬 키워드 검색. 검색 결과 목록 자체는 저장하지 않는다. 사용자가 즐겨찾기·최근 장소로 직접 고른 장소의 이름·좌표는 기기에만 저장하며, 다시 고를 때 재검색 없이 적용한다. 서버로 보내지 않는다.
- 결정 근거: 사용자 결정(2026-11-15), 저장한 장소를 지연 없이 바로 적용하는 것을 우선한다(#39, #16).

- 최근 장소는 수단과 함께 최대 20개를 저장한다. 같은 장소는 맨 위로 올리고, 항목 삭제·전체 삭제를 제공한다(#16).

### 4.2 경로
- 대중교통: 카카오맵 대중교통 경로 조회(`/v2/routing/publictraffic`, 일 1,000건 무료)
  - 출발 시각을 지정할 수 없어 호출 시점 기준 경로를 쓴다
  - 확인 결과(#8 첫 호출, 2026-11)
    - 지하철 단계에도 `path.points` 좌표가 들어온다(선로를 따라 수백 개). 버스·도보 단계도 마찬가지다
    - 출발지→첫 승차 정류장, 마지막 하차→도착지 도보는 응답에 없다. 경로는 승차 정류장에서 시작한다
    - 단계 소요시간 합은 대기·접근 시간을 뺀 값이라 `totalTime`보다 짧다
    - 도시 간 장거리: 서울역→부산역, 서울역→대구는 `NO_RESULTS`. KTX·일반 열차·고속버스 경로는 나오지 않는다. 서울역→대전처럼 시외버스(`vehicles.type` 시외)와 시내버스를 이어 갈 수 있는 구간만 BUS 경로로 나온다
  - 경로가 없을 때 안내: "대중교통 경로를 찾지 못했어요. 열차·고속버스 같은 도시 간 구간은 아직 지원하지 않아요." 대안으로 자가용 경로를 보거나, 출발지에서 역·터미널까지처럼 시내 구간으로 나눠 검색하도록 안내한다
- 자가용: 카카오모빌리티 자동차 길찾기(일 10,000건 무료). 경로 결과는 저장하지 않는다

### 4.3 API 키
- `KAKAO_REST_API_KEY`는 `local.properties`에만 두고 커밋하지 않는다. CI는 빈 키로 빌드한다

## 5. 품질 기준
- 색에만 의존하지 않고 좌·우를 글자로도 구분한다
- 밖에서 햇빛 아래 보는 앱이므로 대비를 우선한다
- 화면은 `docs/DESIGN.md`(#18)를 따르고 스크린샷·접근성 검사와 독립 디자인 리뷰를 거친다

## 3D 이동·햇빛 시뮬레이션 (#56)

수단별 표준 차량의 3D 장면을 제공한다. 이동 경로와 같은 재생 시각에
태양 위치·높이·입사 방향을 갱신하고 선택 좌석의 좌판·등받이에 닿는
직사광 영역을 표시한다. 좌석 선택은 추천과 독립적이며 환승 구간마다 유지한다.
전체/좌석 시점, 수동 탐색, 일시정지·배속을 제공하며 동작 줄이기 설정에서는
자동 재생을 제공하지 않는다. 표준 모형의 예상 범위임을 안내하고 실제
차량·건물·날씨·선팅·커튼·다른 승객 및 신체·UV/열 노출은 보장하지 않는다.
3D 초기화 실패 시 재시도와 텍스트 범위를 제공한다. 실제 지도와 GPU 장면은
기기에서 검증하며 테스트 대체 장면을 실제 구현으로 간주하지 않는다.

시뮬레이션에 들어가면 출발→도착 이동을 자동 재생한다. 위 지도에서도 현재 위치·시간 흐름·진행 방향·해의 위치와 대략적인 햇빛 방향을 확인할 수 있어야 한다. 아래 3D는 같은 재생 시각의 좌석 상세 범위에 집중한다. 수동 일시정지 복원과 동작 줄이기 예외를 유지한다.
