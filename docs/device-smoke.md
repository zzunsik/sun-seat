# 실기기 기본 점검 스크립트 (#169)

`scripts/device-smoke.sh`는 연결된 Android 기기에서 debug 빌드를 실제 터치로 조작하고, `uiautomator dump`로 읽은 화면 노드의 위치로 주요 흐름과 전환을 통과/실패로 판정한다. Robolectric 테스트가 재현하지 못한 끌기→누르기, 시트 올렸다 내리기, 미리보기 닫기, 회전, 큰 글자를 매번 같은 방법으로 확인하려고 만들었다(`docs/bug-analysis-2026-11.md` 5.2).

- 실기기가 기본이다. Android 에뮬레이터는 선택적 교차 확인이다(아래 "에뮬레이터").
- 로컬 전용이다. CI에서 기기를 돌리지 않는다.
- 앱 기능은 바꾸지 않는다. debug 빌드만 Compose 테스트 태그를 리소스 ID로 내보낸다(`MainActivity`의 `testTagsAsResourceId`). release 빌드에는 영향이 없다.

## 언제 돌리나

- 지도 카메라·표식, 시트·제스처, 회전, 시스템 바에 닿는 PR: auto-merge 전에, 마지막으로 `develop`을 합친 최종 커밋의 debug 빌드로 해당 흐름을 실기기에서 돌리고 결과를 PR에 적는다.
- 그 밖의 화면 PR: 전체 흐름 결과를 적거나, 못 돌렸으면 "실기기 미검증"과 사유를 적는다.

## 준비

- bash(Linux·macOS, Windows는 Git Bash), `adb`(PATH, `ADB` 환경 변수, 또는 `ANDROID_HOME`·기본 SDK 위치의 `platform-tools`)
- 기기는 `adb devices`에 `device`로 보여야 한다. 스크립트는 `adb connect`·`disconnect`·`kill-server`를 쓰지 않는다. 연결은 직접 한다.
- 잠금 화면이 없거나 풀려 있어야 한다. 꺼진 화면은 스크립트가 `KEYCODE_WAKEUP`으로 깨우고, 그래도 잠금 화면이면 아무것도 하지 않고 끝낸다(종료 코드 3).
- 카카오 키가 들어간 debug APK(`./gradlew assembleDebug`, 키는 `local.properties`). 경로 검색·지도에 실제 카카오 서버를 쓴다.

## 실행

```bash
./gradlew assembleDebug
scripts/device-smoke.sh -s <serial> --apk app/build/outputs/apk/debug/app-debug.apk
scripts/device-smoke.sh -s <serial> --flows 2,4          # 일부 흐름만
```

| 인자 | 환경 변수 | 뜻 |
| --- | --- | --- |
| `-s <serial>` | `ANDROID_SERIAL` | 기기. 없으면 연결된 기기가 하나일 때 그 기기 |
| `--apk <apk>` | | 점검 전에 설치할 debug APK. 없으면 설치된 앱을 쓴다 |
| `--flows <목록>` | | 흐름 번호(쉼표). 기본 `1,2,3,4,5,6,7,8` |
| `--lock-dir <dir>` | `SMOKE_LOCK_DIR` | 공용 기기 잠금 폴더(아래) |
| `-o <dir>` | `SMOKE_OUT` | 결과 폴더. 기본 `${TMPDIR:-/tmp}/sun-seat-device-smoke/<시각>`. 저장소 안이면 거부한다 |
| `--no-capture` | | 실패한 흐름의 화면 캡처를 남기지 않는다 |
| | `SMOKE_FORCE_3D=1` | 에뮬레이터에서도 흐름 6·7을 돌린다 |

종료 코드: 0 모두 통과(건너뜀 포함), 1 실패한 흐름 있음, 2 사용법 오류, 3 기기를 쓸 수 없음(잠금 사용 중·연결 없음·잠금 화면·앱 없음).

### 공용 기기 잠금

여러 사람·에이전트가 한 기기를 같이 쓰면 각자 정한 잠금 폴더를 `--lock-dir`로 준다. 스크립트는 시작할 때 그 폴더를 만들고(`mkdir`, 원자적), 이미 있으면 다른 사용자가 쓰는 중으로 보고 기기를 건드리지 않은 채 종료 코드 3으로 끝낸다. 만들었으면 `owner.txt`에 스크립트 이름·프로세스 번호·시각을 적고, 끝날 때(실패·중단 포함) 지운다. 남의 잠금 폴더는 지우지 않는다. 잠금 폴더 위치는 각자의 로컬 규칙이며 저장소에 적지 않는다.

### 바꾸고 되돌리는 기기 설정

- 글자 크기 `settings system font_scale`(흐름 6에서 1.5), 회전 `accelerometer_rotation`·`user_rotation`(점검 중 자동 회전을 끄고 세로로 고정, 흐름 5에서 가로).
- 시작할 때 값을 읽어 두고, 끝날 때(실패·Ctrl+C 포함) 그 값으로 되돌린다. 마지막 줄 "설정 복원"에 복원 뒤 값과 시작 값을 함께 출력한다.
- 앱은 시작할 때마다 강제 종료 후 다시 연다. 앱의 최근 장소에 서울역·강남역과 흐름 8에서 고른 강남역 근처 위치가 남는다.

## 흐름과 판정

모든 위치는 화면 px이며, 출력에 dp를 함께 적는다. 검색은 공개 장소(서울역 → 강남역)만 쓴다. `adb input text`가 한글을 넣지 못해 영문 이름(`Seoul Station`, `Gangnam Station`)으로 찾고 결과에서 `서울역`, `강남역 …`을 고른다.

| 흐름 | 조작 | 판정 | 관련 |
| --- | --- | --- | --- |
| 1 | 서울역 → 강남역 후보 목록 첫 진입 | 헤더(`candidates_header`) 아래끝 ≤ 시트 손잡이(`candidates_sheet_handle`) 위끝, 그 사이 지도 띠 > 0 | #167 |
| 3 | 손잡이를 누른 채 약 60dp 올리고(그 상태로 화면을 읽음) 제자리로 내린 뒤 뗌 | 누른 채 시트가 따라 올라감, 뗀 뒤 손잡이가 처음과 8dp 안, 지도 띠가 다시 보임, debug 로그(`SunSeatMapCamera`, #168)의 지도 발자국(경로 외곽·표식 상자 px)이 처음과 같음 | #148 |
| 2 | 손잡이를 끌어 완전 확장 → 카드(두 번째, 없으면 첫 번째) 누름 | 완전 확장(지도 띠 없음, 손잡이가 헤더 바로 아래), 누른 뒤 미리보기(`candidates_preview_sheet`) 열림 | #162 |
| 4 | 흐름 2의 미리보기를 뒤로 가기로 닫음 | 미리보기 닫힘, 시트가 다시 완전 확장, 고른 카드가 48dp 이상 보이고 선택 상태로 펼쳐짐(`route_timeline_<n>`) | #145 #135 |
| 5 | 목록에서 가로로 회전 → 카드 누름 → 미리보기에서 세로로 회전 → 닫음 | 가로 목록에 카드 1장 이상(48dp 이상) 보임, 가로에서 미리보기 열림, 세로로 돌려도 미리보기 유지, 닫으면 카드 1장 이상 | #144 |
| 6 | 글자 1.5배로 자리 보기 → 햇빛 따라가기 | 정보 카드(`simulation_info_card`)가 지도(`simulation_map`) 안에 들고 그 아래로 지도가 48dp 이상 보임, 본문(`simulation_details`) 아래끝 ≤ 조작 패널(`simulation_controls`) 위끝, 카드·패널 안에서 시작한 글자가 경계를 넘지 않고 본문 글자가 패널 밑으로 들어가지 않음 | #113 #155 #161 |
| 7 | (글자 크기 복원 뒤) 지도를 끌어 따라가기 끄기 → 따라가기 누름 | 따라가기 줄(`simulation_follow_row`)이 지도 아래끝보다 아래, 본문 위끝보다 위, 버튼이 줄 안, 누르면 줄이 사라짐 | #122 |
| 8 | 입력 화면에서 도착지 강남역 → 도착 다시 열기 → 지도에서 선택 → 핀을 조금 옮김 → 도착지로 선택 | 지도 선택 화면이 열리고, 주소를 받은 뒤 선택 버튼이 켜지고, 선택하면 입력 화면으로 돌아와 도착지가 바뀜(이름은 출력하지 않음) | #85 |

흐름 1·3·2·4·5는 한 번 준비한 후보 목록에서 이 순서로 이어서 돈다. 흐름 2가 미리보기를 열지 못하면 흐름 4는 실패로 적는다. 흐름 6·7과 8은 앱을 다시 열어 따로 준비한다.

## 결과

- 화면 출력과 결과 폴더의 `summary.txt`에 흐름마다 판정 근거(노드 bounds, 차이 dp)와 `[PASS]`·`[FAIL]`·`[SKIP]` 줄, 마지막에 요약이 나온다.
- 실패한 흐름은 결과 폴더에 그때의 화면 덤프(`flow<n>-fail.xml`), 화면 캡처(`flow<n>-fail.png`), 앱이 죽었으면 크래시 로그(`flow<n>-crash.txt`)를 남긴다.
- 결과 폴더는 로컬 전용이다. 덤프·캡처에는 상태 표시줄 알림이나 현재 위치 주변 주소가 들어갈 수 있으므로 커밋하지 않고 PR에도 올리지 않는다(AGENTS.md "데이터와 개인 정보"). PR에는 `[PASS]`/`[FAIL]`/`[SKIP]` 줄과 요약만 붙이고, 기기 시리얼·로컬 경로는 뺀다.

## 에뮬레이터

- 설치: 카카오 지도 SDK에는 arm 라이브러리만 있다. `--apk`로 설치하면 기기가 arm64를 지원할 때 `--abi arm64-v8a`로 설치해 x86_64 에뮬레이터에서도 arm64 변환으로 지도가 뜬다. 직접 설치할 때도 같은 옵션을 쓴다.
- 흐름 6·7은 에뮬레이터에서 건너뛴다. 햇빛 따라가기의 3D(Filament)가 arm64 변환에서 네이티브 오류로 종료된다. `SMOKE_FORCE_3D=1`로 강제할 수 있다.
- 에뮬레이터는 배치·회전·큰 글자·흐름 교차 확인용이다. 네이티브 지도 카메라·표식, 3D, 실제 손가락 제스처 확인을 대신하지 않는다.
- 스크립트는 에뮬레이터를 설치·다운로드·시작하지 않는다.

## 한계

- 지도 안의 표식·이름표는 접근성 트리에 없어 볼 수 없다. 흐름 3은 debug 빌드가 남기는 지도 카메라 로그(`SunSeatMapCamera`: 모드·줌·보이는 영역·경로 외곽 상자·표식 상자, px, 좌표 없음, #168)로 표식 위치를 비교한다.
- 판정은 접근성 노드의 화면 경계로 한다. 노드 경계는 보이는 영역으로 잘려 나오므로, 부모가 잘라낸 글자 넘침은 잡지 못할 수 있다. 화면 캡처는 사람이 볼 때 쓴다.
- 후보 경로와 개수는 실행 시각의 실제 경로 검색 결과를 따른다. 카드가 하나뿐이면 첫 카드를 쓴다.
- 탭은 노드 가운데를 누른다. 다른 창(알림, 시스템 대화 상자)이 앞에 뜨면 실패할 수 있다.
