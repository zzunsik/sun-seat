# 참고 앱 조사

방향을 정하기 위해 날씨·교통 분야에서 잘 만든 앱의 공개 화면을 살펴보고, 햇빛 좌석에 가져올 것과 피할 것을 정리했다. 화면을 복제하지 않고 원칙만 가져온다. 캡처·로고·브랜드 색·고유 문구는 이 저장소에 넣지 않는다(AGENTS.md "외부 자료와 라이선스").

| 앱 | 가져올 것 | 피할 것 |
|---|---|---|
| Google 날씨(Pixel) | 첫 화면에 결론 한 줄과 큰 숫자. 시간 흐름을 가로 막대로 보여 주는 방식 | 배경 일러스트가 정보를 가리는 장면 |
| Apple 날씨 | 시간대별 값을 한 줄 타임라인으로 압축. 카드마다 제목 한 단어로 위계 정리 | 반투명 카드 위 흐린 회색 글자(햇빛 아래 읽기 어려움) |
| Citymapper | 구간(leg)마다 수단 아이콘·노선·시간을 한 줄로. 결론("이 칸에 타세요")을 행동 언어로 | 정보 밀도가 높아 처음 보는 사람에게 복잡함 |
| Transit | 큰 글자와 높은 대비. 지금 해야 할 일 하나를 화면 맨 위에 | 노선 색 위주 구분(색만으로 구분) |
| 카카오맵·네이버 지도 | 한국어 지명·노선 표기 관습, 검색 → 후보 → 상세 흐름. 범주+개수 탭, 현재 정렬 메뉴, 소요시간 먼저·시간 비례 막대·연결 승하차 타임라인, 후보 탭 후 별도 지도+상세 상태(#97 실기기 비교) | 브랜드 파랑·로고 복제, 공급하지 않는 실시간 정보 흉내. 좌석 결론은 이 앱의 중심으로 유지 |

## 정리한 원칙

1. **결론 먼저.** 결과 화면 맨 위에 "왼쪽 창가에 앉으세요" 같은 행동 문장과 근거 숫자 두 개(그늘·햇빛 시간)를 둔다.
2. **시간은 가로 막대로.** 좌·우 햇빛을 구간 진행에 따라 두 줄 막대로 보여 준다. 막대 옆에 항상 글자 라벨(왼쪽·오른쪽, 햇빛·그늘)을 붙인다.
3. **밖에서 읽힌다.** 정보는 불투명한 면에 진한 글자로. 보조 글자도 회색을 너무 연하게 쓰지 않는다.
4. **한 화면 한 행동.** 화면(또는 열린 시트)마다 채움 주 행동 버튼은 하나다. 채움은 행동색(청록)이며 해 색은 버튼에 쓰지 않는다(`DESIGN.md` 2.3, 13). #154 전에는 중립 잉크색이었다.
5. **해와 그늘이 곧 의미다.** 해(호박색)와 그늘(남보라, #154 전 짙은 남색) 두 색을 의미 색으로만 쓰고 장식 색으로 남발하지 않는다.

## 시각 방향 조사와 선택 (#154, 2026-11-25)

#97은 정보 위계·밀도·상태를 정했지만 색·모양·분위기는 정하지 않았다. 기준 이미지(`input_filled_light`, `candidates_list_light`, `simulation_middle_light` 등)를 보면 색이 검정·회색과 청록 조금뿐이라 와이어프레임처럼 보이고, 선택 상태(수단 `✓ 대중교통`, 재생, 배속)가 큰 검정 덩어리라 소요 시간·햇빛 결과보다 조작부가 더 강했다. 부품 모양도 사각 블록·알약·외곽선 버튼·회색 배지가 섞여 있었다. #154는 이 문제를 시각 방향으로 풀기 위해 참고 조사를 하고 시안 세 개를 비교했다.

### 참고 조사: 가져올 것과 가져오지 않을 것

| 참고 | 가져올 것 | 가져오지 않을 것 |
|---|---|---|
| 카카오맵(실기기 비교, #97·#154) | 흰 바탕 목록, 소요시간을 가장 크게, 한 가지 강조색으로 "지금 고른 것"을 표시하는 관례. 범주 탭·정렬 메뉴·행+구분선 목록 구조는 #97에서 이미 따랐다 | 브랜드 파랑과 로고, 광고 자리, 실시간 도착·혼잡도처럼 우리가 공급하지 않는 정보 |
| Transit | 큰 숫자와 높은 대비, 다음 행동 하나를 화면 위쪽에 크게 두는 태도 | 노선 색으로 화면 전체를 칠하는 방식(우리는 노선 색을 보조 점·막대에만 쓴다, `DESIGN.md` 2.4) |
| Citymapper | 구간을 한 줄로 요약하고 결론을 행동 문장으로 말하는 방식 | 한 화면에 정보를 촘촘히 쌓는 밀도와 브랜드 특유의 색·말투 |
| Material 3 Expressive | 크게 둥근 모서리, 연결형 버튼 묶음, 막대형 손잡이와 굵은 트랙의 슬라이더, 스프링 움직임(앱은 이미 `MotionScheme.expressive()`를 쓴다) | Material You 배경화면 색(해·그늘 의미가 기기마다 흔들린다), 기본 보라 테마, 모양 바꿈 장식 |
| 토스 디자인 시스템 | 흰 바탕에 옅은 면, 강조색 하나, 큰 숫자와 짧은 문장, 크게 둥근 카드 | 브랜드 파랑·전용 글꼴·고유 문구. 글꼴은 지금의 Pretendard를 유지한다 |
| Google 날씨·Apple 날씨 | 결론 한 줄 + 큰 숫자, 시간 흐름을 가로 막대로 보여 주는 방식(위 표와 같다) | 배경 일러스트·반투명 카드·흐린 글자 |

### 세 방향

같은 화면 네 개(입력·후보 목록·자리 결과·햇빛 따라가기)를 밝음/어두움, 큰 글자 예시와 함께 세 방향으로 그려 비교했다. 비교 페이지는 저장소 밖에 두었다.

| 방향 | 한 줄 요약 | 특징 |
|---|---|---|
| A "낮 하늘" | 햇빛 앰버와 그늘 블루를 넓게 쓰는 따뜻한 톤 | 의미 색 면을 크게 써서 햇빛·그늘 정체성이 가장 강하다. 대신 의미 색과 조작부 색이 섞이기 쉽다 |
| **B "또렷"** | 흰 바탕, 청록 한 가지 행동색, 크게 둥근 면, 굵은 슬라이더, 큰 숫자 | 누를 곳과 결론이 가장 분명하다. 해·그늘 색은 의미에만 남는다 |
| C "시간표" | 차분한 고밀도 톤, 표와 시간축 중심 | 비교 밀도가 가장 높다. 밖에서 한눈에 읽기에는 무겁다 |

### 선택 (저장소 소유자, 2026-11-25)

- 색·모양은 **B "또렷"** 하나로 네 화면을 맞춘다.
- 배치는 화면마다 고른다: 입력 = A(햇빛 목적을 두 칸 타일로 꺼냄), 후보 목록 = A의 요소(햇빛 구간 띠·추천 이유 배지·"자리 보기" 톤 캡슐)를 #97의 행+구분선 구조 위에, 자리 결과 = B(결론 + 숫자 타일 두 개), 햇빛 따라가기 = B(큰 현재 시각, 굵은 슬라이더, 큰 재생 버튼).
- 청록은 경로색 값(`#0B6E75` / `#5FC6CC`)으로 통일하고 "청록 = 행동과 경로"로 규칙을 고쳤다. 지도 고정 값(#100 실기기 검증)은 그대로다.
- 햇빛 따라가기 지도는 세로 2:3을 유지한다. 소유자 메모("또렷 스타일에서도 햇빛 현황이랑 슬라이더에 시간 표시", "지도 화면이 좀 더 컸으면")는 정보 카드·시간 눈금 유지로 반영했고, 지도를 더 키울지는 구현 이슈에서 실기기로 정한다.
